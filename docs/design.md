## 剧情：兰斯10式任务地图（走格子）

每个章节是一张任务地图（`godot/data/story.json`，规则在 `scripts/core/quests.gd`）：格子按列从左到右排，**一格一格前进、不能后退**，岔路自己选。

| 格子 | 效果 |
|---|---|
| 事（剧情） | 剧情文字，可带立绘、可送卡 |
| 选（抉择） | 三选一等：选中的武将加入，走向不同分支；**选择会被记住**，重开任务也不用再选 |
| 战（战斗）/ 将（首领） | 必须打赢才能继续 |
| 宝（宝箱） | 亮出几张兵卡，选 1 张 |
| 募（招募） | 亮出几位武将（或本地名单），选 1 位 |
| ？（奇遇） | 开章就发好的随机事件 |
| 休（回复） | 体力回满，累积技能的 AP 加价和限 1 次技能重置 |

和兰斯10一样，**任务中体力不会自动回满**：每场战斗受的伤、累积技能的加价都会带到下一场，只有「休」格或任务结束才重置。
所以「宝箱还是回复」这种岔路是真正的取舍。
输掉战斗：退回上一格、体力回满再来（`Quests.fail`）；设置里还有「重返上一格」「重打这一章」。

格子坐标：`x` 列、`y` 行（0–2）；连线只能走到下一列的相邻行（地图才画得出来，测试守着）。

### 分支设计：借鉴兰斯10 + 《杀戮尖塔》

一个分叉点如果只是换一句台词、两边格子数和内容类型完全一样，就不值得占一个分叉——不如直接合并成一条线（北线第一章
「账房一问」那个分叉就是反例，后来砍掉了）。真正值得做成分叉的，是**两边给的东西不是一回事**，让玩家在「选哪条」的时候
真的要权衡取舍，不是只看一眼哪句台词更对胃口：

- **兰斯10** 的任务地图经常是「这条线拿资源更猛但更凶险，那条线更稳但收获少」——宝箱 vs 回复格就是最直接的例子（见上面
  「宝箱还是回复」那段，测试量过两条线胜率差了一大截，这才叫真选择）。
- **《杀戮尖塔》** 的地图设计同理：一条路线上堆着更多战斗（更多卡/药水，但体力耗得更凶），另一条路线事件/商店/宝箱更密
  （更安全，但战利品薄一些）。玩家选的不是「我喜欢哪种气氛」，是「我现在缺什么、能不能扛」。

套到这个项目最实用的落地方式：**一条分支多战斗（多普通/精英战，换更多兵卡/宝物，但要承担体力损耗和输掉的风险），另一条
分支多 rogue（多事件/宝箱/角色互动，零战斗，但收获也薄一些）**。两条线格数不用完全相等，但走完都要能单独读成一段完整的
小故事，而不是「正确答案」和「陪跑选项」。

实例：北线第一章 `jz_route`（选路，`jz_relief` 之后）——「官道」（`jz_road_fight` 普通战斗，打完接共用的 `jz_mystery1`
？格）vs「小路」（`jz_curious` 甄宓好奇心事件，接新的 `jz_loot_path` 宝箱格，零战斗），两边在 `jz_zuoci` 汇合。参考南线
`plan`（`sc_gate`/`zy_lure` 两条分支）和北线 `jz_plan`（赵云正门强攻 / 郭嘉火攻疑兵，两条都是战斗路线，走的是「选谁入队」
而不是「打不打」的分支逻辑——这是另一种合法的分支模式，不是每条分支都必须是「打 vs 不打」）。

难度基准由机器人跑整章的胜率守着：`godot/tests/test_balance.gd`（目标见 sanguo-test skill）。

## 主公队：亲卫与侍从

主公的部队也有成员：兵种为 `lord` 的兵卡（亲卫、家丁、书童、马夫、侍女，以及丫鬟、绣娘、厨娘、浣纱女、采桑女、茶娘、宫女、伙夫这类伺候人的卡）自动编入主公队，
按 `battle.lord_member_mult`（0.6）计入主公队长的攻击 / 体力（`SaveData.party_leaders`）。它们没有技能、不能当队长（`validate_party` 拒绝），只让主公变强；
南线有「江东亲卫」，北线有「常山亲卫」和甄府的丫鬟 / 绣娘 / 厨娘 / 家丁（`scope` 分开），通用的有主公亲卫、家丁、书童、马夫、贴身侍女、扈从骑。宝箱和招贤格照旧按 `scope` 开出它们。

## 南北线：结构对称，其余分开

南线（江东班底）和北线（河北班底）**结构对称**——章节数、每章的节奏（战斗线 / 探索线、休整、首领）、机制（天命、词缀、主角卡、换人……）一一对应；**除此之外一律分开**：

| 东西 | 怎么分开 |
|---|---|
| 章节 | 各自的 quest（`requires` / `unless` 按出生点分流；第一章是同一个 quest 里的两段） |
| 兵卡 | 卡上的 `scope`（south / north / 空＝两边通用），宝箱按章节的 `soldier_scope` 取 |
| 武将 | 同样的 `scope`：招募 / 宝箱开出的武将只来自自己这条线 + 通用的（古今都用的刘关张、诸葛亮、华佗等）；**拿过的武将**换线也还在池子里 |
| 招贤格 | 每章自己的 `recruit_pool` |
| 随机事件 | 事件的 `scope`（universal / south / north / 某一章） |
| 主角 | 南线刀（突击 + 扔刀）、北线枪（突刺 + 回马枪）；主角卡（`lord_forms`）也按路线发 |
| 结局 | `endings.json` 里每个结局有 `route` |
| CG | 图鉴按「哪一章的格子用它」分组并标南线 / 北线（不看文件名前缀，`c3_` 两条线都有） |
| 美术文件名 | 沿用旧名；新图北线用 `n<章>_` 前缀，南线用 `c<章>_`，别再混用 |

加新东西时先问：它属于哪条线？两边都能用就留空 `scope`，不是的话就写上。测试：`test_the_two_routes_recruit_from_their_own_casts`。

## 战斗与通关的界面约定（Godot 版）

这些是踩过坑之后定下的，改战斗 / 地图界面前先看一遍：

- **图层**：每个盖在地图或战斗上的覆盖层自己设 `z_index`（选卡 70、入队 65、宝物 66、主角卡 70、设置 70……），不要靠加进树的先后。地图上的走路图标是 5，漏设的覆盖层会被它盖住。覆盖层挂在非容器的节点上要**显式写 `size = Vector2(1280, 720)`**，只设锚点会是 0×0。
- **回合上限**：血还有但回合用完也算输。横幅按原因写（回合用尽 / 全军撤退 / 战败），最后两回合用整屏红闪 + 大条提醒（`_alert`）。
- **战斗里的持续特效**（光晕、状态火星、角标、强化卡的放大抬升）在 `_finish` 第一步统一清掉，结束后不再重建；新加任何持续特效都要接进 `_clear_marks`。
- **一行放不下的文字不能撑开面板**：敌人状态、AP、连击都要么自动换行，要么给固定宽度（敌人状态 3 行封顶，体力条可压缩，连击标签留 170 宽）。压力测试用 `--demo=battle --longstatus / --manyap / --lastround / --boost / --endwin`。
- **拿到东西要有「时刻」**：通关发主角卡是全屏动画（`LordReveal`），拿宝物是大卡翻入（`RelicReveal`），入队 / 获得卡牌是 `CardReveal`；`--demo=lordreveal / relicreveal` 单独看。
- **卡牌详情写等级**：武将和主公显示「Lv.N · 铜 / 银 / 金 / 神　N 张」，下一行写再几张升级；兵卡只写张数。
- **弓兵**：南北都要有；北线弓兵靠太史慈（SSR）、马云騄、麹义、白马义从和几张北线弓兵兵卡撑起来。
