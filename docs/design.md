# 设计文档（草案）

目标：三国题材的卡牌策略游戏，**战斗和战役节奏借鉴兰斯10（Rance X）**，**武将收集与武将技借鉴三国群侠传**。
先做文字版，把规则跑通、数值调顺，再考虑图形界面。

## 已有：兰斯10式卡牌战斗（v0.1）

| 规则 | 现状 |
|---|---|
| 行动力 | 每回合固定 AP（虎牢关 = 3），我方 4 名武将抢 3 个行动位 —— “谁这回合出手”是核心决策 |
| 每将一动 | 每名武将每回合最多行动一次 |
| 技能卡 | 每将 2–3 张技能，大招有**每场次数上限**（剩2 / 剩1），部分耗 2 AP |
| 敌方意图 | 回合开始时敌将公开下一步（技能 + 目标），玩家据此决定防御还是抢攻 |
| 回合上限 | 超过回合数即失败（敌军援兵到达），逼玩家进攻而不是龟缩 |
| 状态 | 防御（伤害减半，持续到下回合开始）、士气↑（攻/智 ×1.3）、混乱（失去下一次行动） |

伤害公式：`属性 × 技能倍率 × 100 / (100 + 统率) × U(0.9, 1.1)`，防御再 ×0.5。

## 已有：抽卡 + 编成（v0.2）

- **招募令**：开局 20 张，每胜一场 +10。一张抽一次，不花钱。以后改由剧情发放（兰斯式剧情抽卡）。
- **不重复、无星级**：已拥有的卡移出卡池；某稀有度抽空后，按剩余稀有度的权重重抽。
- **卡 = 兵种 + 武将**：兵种给基础属性和兵种技；武将在上面叠加自身能力和专属技能。
  N 卡是没有武将的基础兵种卡（骑兵队、辎重队……）。战力显示为「兵种 + 武将」两部分。
- **编成**：4 个位置，主公（玩家自己）固定占一位；**同一兵种只能一人指挥**。
- **兵种**：主公、骑、枪、弓、步、谋、后勤（貂蝉、大乔、黄月英等在后勤，负责回复、补行动力、控制）。
- 卡牌数据在 `data/cards.json` 的 `cards`，兵种在 `troops`，概率在 `gacha.rates`。

数值基准（朴素 bot，见 `tests/test_battle.py`）：黄巾之乱用纯 N 卡编成胜率须在 30%–90%；
虎牢关用参考 SR 编成胜率须在 15%–60%；并且 N 卡编成 < SR 编成 < SSR 编成。

**已知问题**：卡池目前只有 32 张，20 次招募就能拿到六成。想要“抽几十次”的手感，卡池得扩到 80–100 张以上。

## 路线图（建议顺序）

1. **战斗打磨** — 更多状态（中毒、灼烧、嘲讽）、敌将 AI 按意图权重而非纯随机、战斗内卡牌（兵法/道具卡，一次性）。
2. **扩充卡池** — 更多武将和兵种技；可能加入编成位随进度增加。
3. **剧情 + 战役层（兰斯10 的另一半）** — 剧情发放招募令、指定武将入队；行动回合制大地图，
   各势力有入侵进度条；事件与招降穿插其中。
4. **存档、多剧本** — 黄巾、虎牢关、赤壁……
5. **界面** — 规则层（`battle.py`）无 I/O，可直接接 Textual（终端 UI）、pygame 或 Web 前端。

## 代码约定

- `src/sanguo/battle.py`：纯逻辑，所有操作返回日志行，不 print、不 input。
- `src/sanguo/cli.py`：只负责显示和读输入。
- `src/sanguo/data/cards.json`：技能、武将、剧本全在这里；加内容优先改数据，不改代码。
- 效果类型（`damage` / `heal` / `guard` / `self_guard` / `atk_up` / `stun`）在 `Battle._apply` 里实现，新效果从那里加。
