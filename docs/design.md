# 设计文档（草案）

目标：三国题材的卡牌策略游戏，**战斗和战役节奏借鉴兰斯10（Rance X）**，**武将收集与武将技借鉴三国群侠传**。
先做文字版，把规则跑通、数值调顺，再考虑图形界面。

## 战斗：照搬兰斯10（v0.3）

规则按兰斯10（RanceX -決戦-）整理。来源：AliceSoft Wiki《Rance X: Game mechanics》
（https://alicesoft.miraheze.org/wiki/Rance_X:Game_mechanics）、rpgcodex 攻略帖、bonsai-desukara / manga-games 攻略博客。

| 规则 | 兰斯10 | 本作 |
|---|---|---|
| 体力 | 全军一条血条 = 所有出战队长体力之和 | 同 |
| 队长属性 | 队长攻击 = 5×自身 + 所属部队其他卡合计（体力同理） | 同；「部队」= 兵种，同兵种所有拥有的卡自动编入 |
| 出战 | 每个部队选 1 名队长，初始 4 个队长位 | 主公 + 3 个兵种队长 |
| AP | 开局 2，每回合 +2，上限 6 | 同 |
| 行动 | 每名队长每回合最多行动一次；技能有固定 AP 消耗，有 0 AP 攻击 | 同 |
| 累积技能 | 每用一次 AP 消耗 +1 | 同（本作在一场战斗内累积） |
| 1 回限定 | 只能用一次 | 同（每场一次） |
| 连击 | 每一击 +10% 伤害 | 同；回合结束清零 |
| 浮动 | 伤害 ±20% | 同 |
| BOOST | ×1.5；3 回合未行动的队长 50% 几率获得 | 同 |
| 插入 | 回合开始时队长部队的成员可能免费攻击一次 | 同，30% 几率，成员攻击×2 |
| 防御 | 防御按钮：30% → 50% → 70% → 90% | 连续防御逐级提升；结束本回合 |
| 敌人 | 一个敌人一条血条；血量随我方队长人数上浮（1 人 6 万 → 7 人 9 万） | 同，每多 1 名队长 +8.3% |
| 胜负 | 敌方体力 0 胜；我方体力 0 或超过回合上限败；可撤退 | 同 |

**尚未实现**：宝箱与卡牌掉落、经验与升级、属性相克、睡眠/中毒等状态异常、敌人分析（アナライズ）。
敌人不预告行动（兰斯10默认也不预告）。

数值基准（朴素 bot 只顾输出、从不防御，见 `tests/test_battle.py`）：山贼战三选一任意一人胜率 > 70%；
黄巾之乱纯 N 卡 30%–90%；虎牢关参考 SR 编成 15%–60%；N 卡编成 < SR 编成 < SSR 编成。

## 已有：抽卡 + 编成（v0.2）

- **抽卡不限次数、不耗资源**，和剧情互不冲突：任何时候都能抽到任何卡池里的人（比如直接抽到吕蒙）。
- **不重复、无星级**：已拥有的卡移出卡池。
- **卡 = 兵种 + 武将**：兵种给基础体力/攻击和兵种技；武将在上面叠加自身能力和专属技能，战力分「兵种 + 武将」显示。
  N 卡是没有武将的基础兵种卡（骑兵队、辎重队……）。
- **同一武将多版本**：主线给固定版本（孙策·少年、周瑜·少年），卡池里有其他版本（孙策·中年、周瑜·赤壁）。
  卡牌用 `person` 字段标记是谁；同一人的不同版本不能同时上阵。剧情专属卡标 `"pool": false`。
- **编成**：4 个位置，主公（穿越者，也就是玩家）固定占一位；同一兵种只能一人指挥。
- **兵种**：主公、骑、枪、弓、步、谋、后勤（吴国太、貂蝉、大乔、黄月英等在后勤，负责回复、补行动力、控制）。

## 卡牌：武将 + 兵卡

| | 武将卡（R / SR / SSR） | 兵卡（兵） |
|---|---|---|
| 来源 | 抽卡（只出武将）、剧情 | 战斗宝箱、地图「宝」格、剧情 |
| 重复 | 不会重复 | 可以重复叠加 |
| 部队加成 | 全额计入 | 同一种兵卡：第 1 张 100%，之后每张 ×0.6（60%、36%…）；换一种兵卡又从 100% 算 |

所以同兵种里收集不同的兵卡（刀兵：刀兵队、长沙刀兵、当阳兵、丹阳兵、陷阵营）比堆同一种更划算。兵卡也能当队长（前期没武将时用）。
兵卡掉率由 `weight` 决定（普通 3、稀有 1）。

**宝箱**（照兰斯10）：战斗胜利后有几率掉宝箱——首领必掉；普通战斗 50% + 过量伤害占敌人体力的比例（最后一击溢出 ≥ 50% 必掉）。
普通宝箱 2 张兵卡，首领 3 张。常量在 `cards.json` 的 `gacha` 里（`soldier_decay`、`chest_base`、`chest_cards`…）。

## 剧情：兰斯10式任务地图（走格子）

每个章节是一张任务地图（`data/story.json`，引擎在 `quest.py`）：格子按列从左到右排，**一格一格前进、不能后退**，岔路自己选。

| 格子 | 效果 |
|---|---|
| 事（剧情） | 剧情文字，可带立绘、可送卡 |
| 选（抉择） | 三选一等：选中的武将加入，走向不同分支；**选择会被记住**，重开任务也不用再选 |
| 战（战斗）/ 将（首领） | 必须打赢才能继续 |
| 宝（宝箱） | 开出 2 张兵卡 |
| 休（回复） | 体力回满，累积技能的 AP 加价和限 1 次技能重置 |

和兰斯10一样，**任务中体力不会自动回满**：每场战斗受的伤、累积技能的加价都会带到下一场，只有「休」格或任务结束才重置。
所以「宝箱还是回复」这种岔路是真正的取舍（测试里：虎牢关任务选回复胜率约 45%，贪宝箱约 2%）。
输掉战斗 = 任务失败，从任务开头重来；已获得的卡和做过的选择保留。

现有地图：序章·穿越江东（三条分支 → 寨前 → 宝箱/山泉二选一 → 山寨首领 → 吴国太）、第一章·黄巾之乱、第二章·虎牢关。
格子坐标：`x` 列、`y` 行（0–2）；连线只能走到下一列的相邻行（地图才画得出来，`load_quests` 会校验）。

数值基准（朴素 bot，见 `tests/test_battle.py`、`tests/test_quest.py`）：序章三选一任意一人整图通关 > 70%；
黄巾之乱任务用序章后的卡组 30%–95%；虎牢关任务弱卡 < 10%、中等卡组选回复 15%–80% 且高于贪宝箱。

## 路线图（建议顺序）

1. **战斗补全** — 宝箱（战后掉卡）、经验升级、属性相克、状态异常、多段敌人行动模式。
2. **扩充卡池** — 更多武将和兵种技；可能加入编成位随进度增加。
3. **剧情 + 战役层（兰斯10 的另一半）** — 第一章起的分支剧情；行动回合制大地图，
   各势力有入侵进度条；事件与招降穿插其中。
4. **存档、多剧本** — 黄巾、虎牢关、赤壁……
5. **界面** — 已有 Textual 终端界面；规则层无 I/O，以后要做 pygame 或 Web 前端也可以直接接。

## 代码约定

- `src/sanguo/battle.py`：纯逻辑，所有操作返回日志行，不 print、不 input。
- `src/sanguo/tui.py`：Textual 终端界面，只负责显示和读输入。`textual serve` 可以把它放到浏览器里。
- `tests/test_tui.py`：用 Textual 的 pilot 无头驱动界面做冒烟测试。
- `src/sanguo/data/cards.json`：技能、武将、剧本全在这里；加内容优先改数据，不改代码。
- 效果类型（`attack` / `magic` / `heal` / `guard` / `boost` / `stun` / `break` / `ap`）在 `Battle._apply` 里实现，新效果从那里加；
  战斗常量（AP、连击、BOOST、防御档位……）在 `cards.json` 的 `battle` 里。
