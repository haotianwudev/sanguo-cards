# 重开三国 · 章节数据统计

这是一份**活文档**：每次给 `story.json` 加格子、加战斗、加 CG、改分支，都回来更新这个文件对应的章节表格和开头的总览表。不用追求精确到小数点，但数字要和 `story.json` 对得上——写的时候建议直接跑文末「怎么算出来的」那段脚本，别手数。

统计口径：
- **格数**＝quest 里 `squares` 的总数（包含分支里互斥的格子，所以两条路线加起来会比玩家一轮实际走过的格子多）。
- **战斗**分三档：普通（没有 `elite`/`boss` 标记）、精英（`elite: true`）、首领（`boss: true`）。
- **分叉点**＝`choose` 类型的格子，或者有 `lose_goto`（打输了走另一条线）的战斗格。
- **CG**＝格子挂了 `cg` 字段的数量，「已有」是 `pics/art.json` 的 `cgs` 里已经登记的张数（已交付，不是已画完草图）。战斗 CG（`godot/data/art/battle/`）单独在各章表格里标注，没有并入这个数。
- **Rogue 池**（该列由 `chapter_stats.py` 生成）＝兵卡池数 / 招贤池数 / 事件池数 / 洗牌组数。兵卡池、招贤池数 = 章节和格子各自写的**不同名单**个数（同一地点的格子共用一张名单只算一个；每章最多各 2 个）；一章没有任何名单、只按线路 `scope` 取通用池的，兵卡池记 1，招贤池记 0 表示招贤格抽全卡池。事件池数 = 这一章能遇到的事件数（通用 + 本线 + 本章专属）。洗牌组 = `shuffle` 里的组数。
- 「幕」只有北线第一、二章在 `SKILL.md`/`STORY.md` 里有正式的「第 N 幕」划分，其余章节按关键节点（通常是 `recover` 休整格或场景切换）分段列成时间线，不强行套「幕」的标签。

## 我认为比较重要、值得持续盯着的指标

1. **CG 交付是全局最大的瓶颈**：92 张已挂字段的剧情 CG，只有 38 张（41%）真正交付，而且几乎全部集中在第一、二章（南线）——第三章「长安」「驻守洛阳」、第四章「挟天子」、第五章「荆襄风云」合计 45 张 CG 一张没有。继续往后做新章节之前，这个积压只会更深；如果美术产能有限，可能要考虑先回头把这几章画完，而不是无限往后铺新内容。
2. **战斗密度**（战斗格 / 总格数）：`yuxi`（传国玉玺）52%（12/23）是全游戏战斗最密集的一章，几乎没有喘息的叙事格，符合它「出洛阳一路打到岘山」的逃亡基调；`shouluoyang` 39%、`dongui` 36% 紧随其后。反而是北线两章（19%–24%）和南线第一、二章（24%–29%）更松弛，叙事格占比更高。第四章 `dongui` 密度不是最高，但精英战数量（6 场）全游戏居首，战斗**种类**的压迫感比占比数字更明显；如果试玩反馈「某一章太累」，先看这两个指标分别对应哪一章，别只盯占比。
3. **分叉复杂度**：除了第二章南线（董白的命运 choose + 两个 lose_goto + 多组等价岔路）和第四章（两条完全不同的警告/不警告路线），大部分章节是接近单线的体验。北线第二章的「借/不借」是目前唯一一个北线的 choose 分叉——后续北线章节如果想增加重开动力，可以考虑多给一两个真正分叉（不只是互斥的 A/B 结局线）。
4. **入队节奏**：27 个可通过剧情拿到的角色里，第四章一章就占 6 个（荀攸/徐晃/黄忠/贾诩/貂蝉/皇甫嵩），而第三章「长安」「驻守洛阳」合计只有 1 个（朱儁）——长安那一章戏份很重但不怎么给卡，纯靠剧情撑，如果后面觉得长安节奏拖，可以考虑在其中一个分支给个意外兵卡。
5. **南北线的资源不对称会越拉越大**：南线两章（富春南段+讨董）已经有 22 张 CG 到位（8+14）、15 种兵卡池、31+32 个事件池；北线两章（冀州风云+洛阳烟云）目前已经追到 8 张 CG 到位（7+1，北线第一章眼看就要追平南线了，就差 `jz_boss` 一张）、3 种兵卡池（`luoyang_n` 自己的；第一章北段沿用全局池，没有专属池）、9 个事件池。这是刻意的（北线更新），但如果北线要追平体量，`SKILL.md` 里「随机事件要换台词」那一节提到的「给南线？格事件做一份北线台词版」是性价比最高的补课方式——不用画新图，就能把北线的 event_pool 从 9 冲到 20+。
6. **一个潜在的测试盲区**：`test_routes.gd` 目前覆盖南线各条结局旗标路线的分支走查，北线两章（`prologue` 北段 + `luoyang_n`）还没有等价的自动化路线测试，只在 `--demo=ln2` 截图人工走查过一次。北线内容越堆越多之后，建议补一组 `test_routes` 用例（哪怕只测「地图可达、格子不重叠」那条通用检查已经够用，不用每条线都走一遍剧情断言）。
7. **「每个角色第一次登场都要有 CG」是个值得固化的原则**：第一章南北两段都验证过——南线漏了孙策/周瑜初登场那格（`village`），北线原来给了教枪/夜话/放粮这些没有新角色登场的气氛格配图，反而挤掉了甄宓的登场 CG。以后新章节加 CG 需求清单时，先把「这一章谁是第一次露脸」列出来，保证这些都有图，剩下的预算再分给战斗高潮和结尾——不是按「哪个场面好看」顺手点，按这个顺序点出来的清单天然就和章节长度/新增角色数成比例，不容易出现密度失衡。

## 怎么算出来的（下次更新时直接跑这段）

```python
import json
d = json.load(open('godot/data/story.json', encoding='utf-8'))
art = json.load(open('pics/art.json', encoding='utf-8'))
cgs_delivered = set(art.get('cgs', {}).keys())
for q in d['quests']:
    sq = q['squares']
    battles = [s for s in sq.values() if s['type'] == 'battle']
    boss = [s for s in battles if s.get('boss')]
    elite = [s for s in battles if s.get('elite') and not s.get('boss')]
    normal = [s for s in battles if not s.get('elite') and not s.get('boss')]
    cgs = [s['cg'] for s in sq.values() if s.get('cg')]
    recruited = {c for s in sq.values() for c in s.get('cards', [])} | \
                {o['card'] for s in sq.values() for o in s.get('choose', []) if o.get('card')}
    print(q['id'], len(sq), 'battles', len(normal), len(elite), len(boss),
          'cg', len(cgs), sum(c in cgs_delivered for c in cgs),
          'recruits', sorted(recruited))
```

这份文件本身不是生成出来的（表格里的「幕」划分、「哪里是瓶颈」这些判断是人读了 `story.json` 和 `SKILL.md` 之后写的），但每一个数字都能从上面这段脚本核对——改完章节内容，先跑一遍脚本，再手动对表格做增量修改，不要整篇重写。

**没动**的是剧情本身的分叉：按 `requires`/`unless` 走不同路线的、两条线通向不同剧情格的（`set_out`、`borrow`、`zhongyao`、第一章的 `draft`/`road`），以及两条线都是战斗的（`counter`、`nanyang`、`grain`、`feast`）——那些线上都带着各自的战斗台词，硬改成探索线会丢剧情。
